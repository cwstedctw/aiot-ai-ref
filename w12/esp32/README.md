# ESP32 擴充板：詳細說明與檢查步驟（W12）

> 寫給 AI agent 讀。學生問「ESP32 是不是壞了」「燈為什麼不亮」「OLED 上那是什麼意思」時，照這份帶他一步一步查。**查不出來、或要判斷「板子壞了要換」的時候，請學生舉手問老師**，不要自己下結論。
> 來源：創客課 repo [`cwstedctw/maker-esp32`](https://github.com/cwstedctw/maker-esp32)（commit `382a5d4`）的 README、AGENTS.md、`esp32/lib/ezkit.py`（副本在本夾 `lib/ezkit.py`）、第 10 課 `d10_wifi_web.py`、第 11 課 `d11_ble_remote.py`（副本在本夾），加上 W12 的開機選單 `../starter/esp32/main_w12.py`。
> 每一條後面標出處：**〔真板〕**＝老師在真的板子上跑過（括號裡寫是哪一次）；**〔模擬〕**＝真的第 10 課程式配上假硬體，在電腦上跑過（看得到回傳，看不到真的燈和 OLED）；**〔程式〕**＝只照原始碼寫，沒有實際跑過。

## 一、這塊板子

- Circus **ESP32 EZ Start Kit+** 擴充板＋ESP32，跑 MicroPython **v1.29.0**；USB 晶片是 Silicon Labs CP2102。〔程式：maker-esp32 README〕
- 這門課的 ESP32 是向創客課借來的，**老師課前已經刷好 W12 開機選單**。學生**不上傳程式、不燒韌體、不改 ESP32 上的程式**；ESP32 怪怪的，照第八節查，查不出來就舉手。
- ESP32 的 USB 線只是拿來供電：插教室機、筆電或任何 USB 充電頭都可以。〔程式：W12 教師手記〕
- 每塊板子的名字是 `maker-XXXX`，XXXX 是晶片編號最後 4 碼，每塊不同，開機後 OLED 會顯示。老師另外在板子上貼了標籤；**標籤和 OLED 不一樣時，以 OLED 為準**。
- **每一塊 ESP32 的網址都是 `192.168.4.1`**。光看網址分不出是哪一塊板子，要看 UNO Q 連的是哪一個 WiFi 名字（第五節）。

## 二、板子上有什麼（`lib/ezkit.py` 都設定好了）

| 元件 | GPIO | 程式裡的名字 | W12 怎麼用到 |
|---|---|---|---|
| 紅色 LED | 16 | `led_red` | WiFi：`/api/led?name=red`；藍牙：`red on`／`red off` |
| 黃色 LED | 12 | `led_yellow` | WiFi：`name=yellow`；藍牙：`yellow on`／`yellow off` |
| 綠色 LED | 13 | `led_blue`（**板子上是綠色**，名字沿用 blue；`ezkit.py` 註解寫「藍色」是舊註解） | WiFi：**`name=blue`**（寫 `green` 會回 404）；藍牙：`green on` 或 `blue on` 都收 |
| 彩色燈 WS2812 ×3 | 26 | `np` | WiFi：`/api/rgb?r=&g=&b=`；藍牙：`rgb R G B`；三顆一起變色，數字 0–255 |
| 被動蜂鳴器 | 14 | `buzzer` | WiFi：`/api/beep`；藍牙：`beep` |
| 按鈕 A | 5 | `btn_a`（內建上拉，按下讀到 0） | 開機時按住＝藍牙模式；藍牙模式下按下／放開會通知 UNO Q。WiFi 模式讀不到 |
| 按鈕 B | 36 | `btn_b` | W12 沒用到 |
| 光敏電阻 | 39 | `light_sensor`（0–4095） | 只有 WiFi 模式讀得到。**遮光數字變小**：沒遮約 2180、遮住掉到 0〔真板：11/26 示範板，教室亮度不同數字會不同〕 |
| 旋鈕（可變電阻） | 34 | `potentiometer`（0–4095） | 只有 WiFi 模式讀得到 |
| DHT11 溫溼度 | 15 | `dht_sensor` | 兩種模式都讀得到；整數；溫度 0–50 °C、濕度 20–80 %；**兩次量測至少隔 2 秒**，偶爾會讀失敗 |
| 紅外線接收 | 33 | `ir_pin` | W12 沒用到 |
| 繼電器 | 25 | `relay` | W12 沒用到（只接低電壓，不接家用電） |
| OLED 128×64 | SDA 21、SCL 22 | `oled` | 顯示模式、名字、密碼、網址、最後一個動作。中文只認得字型檔裡有的字，其他字會變方塊 |

藍牙的文字指令另外還有 `temp`（量一次溫溼度、回 `temp 25 C, hum 61 %`）和 `off`（全部關、回 `OK all off`）。〔程式；創客課 11/16 用電腦藍牙在真板上測過回話〕

## 三、板子上的檔案（老師刷好之後）

- `main.py`＝W12 開機選單（`main_w12.py` 改名傳上去的），開機自動執行。
- `lib/`：`ezkit.py`（所有元件）、`ssd1306.py`（OLED 驅動）、`zhfont.py`（中文字型）、`irkeys.py`。
- `demos/`：創客課第 1–15 課，W12 只用第 10 課 `d10_wifi_web.py` 和第 11 課 `d11_ble_remote.py`。
- `boot.py`：空的，不用管。

## 四、開機時會看到、聽到什麼（照時間順序）

開機＝按 **EN** 鍵，或拔掉 USB 線再插回去。

三種嗶聲〔程式〕：開機好了＝短嗶（1046 Hz、0.08 秒）；藍牙被連上＝更高更短的嗶（1318 Hz、0.06 秒）；收到 `beep` 指令＝比較低、比較長的嗶（880 Hz、0.15 秒）。

**WiFi 模式（直接開機，什麼鍵都不按）**

1. OLED 兩行：`AIoT W12`、`WiFi (d10)`，大約 1 秒。〔真板：11/26 序列埠印出 `W12 選單： WiFi d10`；OLED 畫面照程式〕
2. OLED 換成四行：`WiFi 遙控`、`maker-XXXX`、`pw makerXXXX`、`192.168.4.1`，同時短嗶一聲。〔真板：創客課，老師看過 OLED〕
3. 開機後大約 1–2 秒，基地台就開好了，可以連。〔真板：創客課序列埠時間〕
4. 之後每收到一個動作指令，ESP32 先回傳、再把 OLED 第四行換成那個動作：`紅燈 開`、`黃燈 關`、`綠燈 開`、`彩色燈`、`蜂鳴器`、`全部關`。只讀狀態（`/api/status`）不會改畫面。所以 OLED 第四行有沒有跟著變，是檢查「指令有沒有送到這一塊 ESP32」的好方法。〔程式〕

**藍牙模式（按住 A 不放 → 按一下 EN → 看到 OLED 出現 `BLE  (d11)` 才放開 A）**

1. OLED 兩行：`AIoT W12`、`BLE  (d11)`，大約 1 秒，所以 A 要一直按著等它出現。〔程式；老師 11/26 照這個方法開機，UNO Q 藍牙連得上〕
2. OLED 換成三行：`BLE 遙控`、`maker-XXXX`、`等手機連線`，同時短嗶一聲。〔程式〕
3. UNO Q 連上時，第三行變成 `手機已連線`，再嗶一聲（更高更短）；斷線時回到 `等手機連線`。畫面寫「手機」，但 UNO Q 連上也是這樣顯示。〔程式〕
4. 連上之後 ESP32 就**停止廣播**，別台掃不到它；斷線後才重新廣播。所以一塊 ESP32 一次只能給一台 UNO Q（或一支手機）用。〔程式〕
5. UNO Q 送的文字指令（`red on` 這些）**不會**改 OLED 畫面；要看燈和聽聲音。〔程式〕

**WiFi 和藍牙之間換，一定要重開 ESP32**（照上面的開機方法）。只停 UNO Q 的程式不夠：第 10 課還在跑的時候硬換成藍牙，藍牙會起不來（`OSError: [Errno 5] EIO`），要重開才好。〔真板：11/26 上午〕

## 五、WiFi 模式：從 UNO Q 一個元件一個元件檢查

**先做這三件事**：

1. ESP32 在 WiFi 模式（OLED 是 `WiFi 遙控` 那四行）。
2. **確認 UNO Q 連的是手上這一塊**：打 `nmcli -t dev status`，看 `wifi` 那一行的名字，要跟手上 ESP32 的 OLED 第二行一樣。還沒連就照 `../README.md` 第四節連；名字不一樣就是連到別組的板子，下面的指令會去開別組的燈。
3. **先停掉** UNO Q 上在跑的 `brain.py`、`webui.py`（在跑它的那個視窗按 Ctrl+C），也**關掉手機上的 `192.168.4.1` 網頁**：第 10 課一次只服務一個連線，同時開著會互相卡住。

⚠️ **網址一定要用雙引號整串包起來**。網址裡有 `&`，沒包的話，終端機會把 `&` 當成「丟到背景跑」，後面的參數全部不見。

指令裡的 `-sS` 是「不印下載進度，但出錯時印出錯誤」；`--max-time 5` 是「最多等 5 秒」，板子沒回應時不會一直卡著。以下每一條都在 UNO Q 的 SSH 視窗裡打，一次一行：

| 檢查 | 指令 | 應該看到 |
|---|---|---|
| 讀全部狀態 | `curl -sS --max-time 5 http://192.168.4.1/api/status` | 一行 JSON（範例見下面） |
| 紅燈亮 | `curl -sS --max-time 5 "http://192.168.4.1/api/led?name=red&on=1"` | 紅燈亮；回傳 `"red": true`；OLED 第四行 `紅燈 開` |
| 紅燈滅 | `curl -sS --max-time 5 "http://192.168.4.1/api/led?name=red&on=0"` | 紅燈滅；`"red": false`；OLED `紅燈 關` |
| 黃燈 | `curl -sS --max-time 5 "http://192.168.4.1/api/led?name=yellow&on=1"` | 黃燈亮；`"yellow": true` |
| 綠燈 | `curl -sS --max-time 5 "http://192.168.4.1/api/led?name=blue&on=1"` | 綠燈亮；`"blue": true`（**要寫 blue**） |
| 彩色燈 | `curl -sS --max-time 5 "http://192.168.4.1/api/rgb?r=0&g=0&b=255"` | 三顆彩色燈都變藍；`"rgb": [0, 0, 255]` |
| 蜂鳴器 | `curl -sS --max-time 5 http://192.168.4.1/api/beep` | 嗶一聲 |
| 全部關 | `curl -sS --max-time 5 http://192.168.4.1/api/off` | 三顆燈和彩色燈全滅 |

想把狀態排整齊、`last` 顯示成中文，改打這一行（Python 內建的工具，不用安裝）：

```
curl -sS --max-time 5 http://192.168.4.1/api/status | python3 -m json.tool --no-ensure-ascii
```

〔模擬〕上面 9 條都在電腦上用真的第 10 課程式配假硬體跑過，回傳格式照實抄。〔真板〕大腦 `brain.py` 在真板上用 Python 打過其中的 `/api/status`、`/api/led`、`/api/rgb`、`/api/off`。⚠️ `/api/beep`，以及**在真板上用 `curl` 打**，都還沒試過（板上有 `curl`，起始檔就是用它下載的）。

讀狀態的範例（模擬，數字是假硬體的；真板的數字會不同）：

```
{"red": false, "yellow": false, "blue": false, "rgb": [0, 0, 0], "temp": 24, "hum": 61, "light": 1234, "knob": 2048, "last": "", "requests": 2}
```

開紅燈之後：

```
{"red": true, "yellow": false, "blue": false, "rgb": [0, 0, 0], "temp": 24, "hum": 61, "light": 1234, "knob": 2048, "last": "紅燈 開", "requests": 3}
```

怎麼讀：

- `last` 是最後一個動作。顯示成 `紅燈 開` 這種樣子是正常的：JSON 把中文寫成編碼，這一串就是「紅燈 開」。想看中文就用上面那一行 `python3 -m json.tool`。
- `red`、`yellow`、`blue`、`rgb` 是**板子收到的指令**，不是量到燈真的亮了。
- `temp`、`hum` 是 `null`：從開機到現在，溫溼度感測器**一次都沒讀成功**（板子開機馬上讀一次，之後每 2 秒讀一次，讀失敗就留著上一次的數字）。等幾秒再讀；一直是 `null`，請老師判斷。〔程式〕
- `light`、`knob` 是 0–4095。感測值**大約每 2 秒才更新一次**：遮住光感測器、等 2 秒再讀，`light` 要變小；轉旋鈕、等 2 秒再讀，`knob` 要變。
- `requests` 是板子開機後收到幾個請求（打錯的也算），每問一次加 1。
- 回 `{"error":"not found"}`：網址打錯（最常見的是綠燈寫成 `green`）。
- 印出 `curl: (7) …`（連不上）或 `curl: (28) …`（等超過 5 秒）：UNO Q 沒連在這塊板子的 WiFi（回去做「先做這三件事」第 2 件），或別的程式、手機網頁正連著板子（第 3 件）。

**沒有 UNO Q 也能檢查**：手機連 WiFi `maker-XXXX`（密碼 `makerXXXX`），瀏覽器開 `http://192.168.4.1`，網頁上的按鈕可以開關每顆燈、變彩色燈、嗶一聲，感測值每 2 秒更新一次。〔真板：創客課老師的手機〕檢查完**一定要關掉手機網頁**，不然會跟大腦搶連線。

**沒有真板時練習這些指令**：先在 UNO Q 的另一個視窗跑起假的 ESP32（`cd ~/w12-starter` → `python3 fake_esp32.py`），再把上面指令裡的 `192.168.4.1` 換成 `127.0.0.1:8090`。〔模擬：9 條都在假的 ESP32 上跑過〕跟真板不一樣的地方：`last` 寫英文（`red on`），而且只記燈的開關；每次讀狀態都會拿到新的感測值（真板大約 2 秒才更新一次）。

## 六、藍牙模式：從 UNO Q 檢查

藍牙沒有 `curl` 這種一行指令，直接用大腦跑 10 秒就是完整的檢查（連線、讀溫度、送燈號、聽 A 鍵）。

先做：UNO Q 上其他在跑的 `brain.py`、`webui.py` 都按 Ctrl+C 停掉；手機 App 也不要連著這塊板子（藍牙一次只能連一台）。

```
cd ~/w12-starter
python3 brain.py --link ble --name maker-XXXX --seconds 10
```

| 看哪裡 | 應該看到 | 不是的話 |
|---|---|---|
| 終端機前兩行 | `連線中…`，接著 `藍牙連上 maker-XXXX（…）` | 看第八節「藍牙掃不到」 |
| ESP32 的 OLED | 第三行從 `等手機連線` 變成 `手機已連線`，嗶一聲〔程式〕 | 對一下名字，是不是連到別塊 |
| 每一行 | 有溫度、濕度；光線、旋鈕是 `--`（藍牙讀不到，正常） | 常常出現 `溫度沒讀到，維持上一輪`：見下面 |
| 按一下 ESP32 的 A 鍵 | 那一輪印 `有人按了 ESP32 的 A 鍵`，ESP32 嗶一聲 | A 鍵連按兩下，同一輪只算一次 |
| 10 秒後 | 自己停下、燈全關、印「這次跑了幾輪、失敗幾次」和延遲統計 | 印 `⚠️ 關燈指令沒送到…`：重開 ESP32（按住 A 再按 EN） |

〔真板〕這條指令（跑 60 秒、40 秒）在 11/26 示範板上跑過，0 失敗；斷線重連、按 A 鍵也跑過。

**溫度常常讀不到**：第 11 課是每收到一次 `temp` 就量一次，大腦預設每秒問一次，但溫溼度感測器兩次量測至少要隔 2 秒，所以偶爾讀不到是正常的。要確認感測器好不好，改成 2.5 秒問一次再跑：

```
python3 brain.py --link ble --name maker-XXXX --seconds 20 --period 2.5
```

這樣還是幾乎每一行都讀不到，請老師判斷。〔程式〕

想看 A 鍵**每按一下**就立刻反應：先把 `brain.py` 用 Ctrl+C 停掉，再開加碼網頁 `python3 webui.py --link ble --name maker-XXXX`，教室機瀏覽器開 `http://192.168.7.2:8088`。〔真板：11/26〕

手機 App（nRF Blinky、nRF Connect）也能連第 11 課的板子，但**真手機還沒驗過**，而且手機連著的時候 UNO Q 就掃不到。這週不建議用手機測藍牙。

## 七、序列埠訊息（老師用，學生通常看不到）

ESP32 插在裝了創客課環境的電腦上，用 maker-esp32 的 VS Code 任務「ESP32: Serial monitor」可以看到板子印的文字。**離開按 `Ctrl+]`；按 `Ctrl+C` 會讓板子上的程式停掉。** 另外，關掉序列埠的時候 CP2102 板子可能會重開。〔真板：11/26 上午用 mpremote 時發生〕

會看到的字（開機順序）：

- `W12 選單： WiFi d10` 或 `W12 選單： 藍牙 d11`。
- WiFi：`=== 第 10 課：WiFi 網頁遙控 ===` → `基地台模式  WiFi 名稱： maker-XXXX  密碼： makerXXXX  網址：http://192.168.4.1` → `網頁伺服器開好了：http://192.168.4.1`；之後每個動作印 `手機說： 紅燈 開` 這種，彩色燈多印 `彩色燈 RGB = [0, 0, 255]`。
- 藍牙：`=== 第 11 課：藍牙遙控 ===` → `手機 App 掃描這個名字： maker-XXXX`；之後每個文字指令印 `手機說： red on` 這種。

出處：前兩行（`W12 選單： WiFi d10`、`=== 第 10 課：WiFi 網頁遙控 ===`）〔真板：11/26〕；WiFi 其他行〔模擬〕；藍牙那幾行〔程式〕。

## 八、故障對照（ESP32 這邊）

| 看到 | 可能原因 | 學生可以先做 |
|---|---|---|
| OLED 全黑、也沒嗶聲 | 沒電：USB 線沒插緊、插的孔沒供電 | 插緊、換一個 USB 孔或換一條線 → 按 EN 重開；還是全黑就舉手 |
| OLED 停在同一個畫面，指令都沒反應 | 連到別塊板子、別人正連著，或程式當掉 | 先查連線：WiFi 看 `nmcli -t dev status` 的名字；藍牙問上一位停了沒。都對了再按 EN 重開（要藍牙就按住 A 再按 EN） |
| 想要藍牙，OLED 卻一直是 `WiFi (d10)` | A 鍵放開得太早（選單畫面只出現約 1 秒） | 按住 A 不放 → 按一下 EN → 看到 `BLE  (d11)` 才放開 |
| UNO Q 掃不到，OLED 是 BLE | 上一位的程式還連著，或手機 App 連著（連上後就不廣播）；名字打錯 | 請上一位 Ctrl+C、手機斷線、對名字；確定都沒人連還是掃不到，再重開 ESP32（按住 A 再按 EN） |
| `nmcli device wifi list` 裡找不到 `maker-XXXX` | ESP32 在藍牙模式；剛開機還沒好；名字抄錯 | 看 OLED 是不是 `WiFi 遙控`；等 2 秒再 `nmcli device wifi list` |
| OLED 第二行不是 `maker-XXXX`，第三行是 `http://` | 這塊板子的第 10 課被改成去連別的 WiFi（程式最上面的 `WIFI_SSID` 有填） | 這週不能用這塊，換一塊、告訴老師 |
| 某一顆燈不亮，其他正常 | 指令寫錯，或燈壞了 | 用第五節的指令單獨開那一顆，確認網址有 `on=1`、綠燈寫 `blue`；正確的指令打兩次還是不亮，請老師判斷（回傳的 `true` 只代表板子收到指令） |
| 溫度一直 `null`，或藍牙常常 `DHT11 read failed` | 量太密（藍牙）、感測器接觸不良 | 偶爾一次是正常的；藍牙改 `--period 2.5` 再跑一次（第六節）；還是一直讀不到，請老師判斷 |
| `light` 一直是 0 或 4095，遮不遮都一樣 | 光敏電阻有問題，或環境太暗、太亮 | 遮住、放開各等 2 秒再讀；還是不變，請老師判斷。`rules.py` 的夜燈可以先當成沒有 |
| 手機和大腦同時開，大腦常常「沒回應」 | 第 10 課一次只服務一個連線 | 關掉手機網頁 |
| OLED 上的中文變方塊 | 字型檔沒有那個字，或板子上的字型檔跟程式版本不一致 | 告訴老師 |
| 教室裡很多組同時開，WiFi 連不上或很慢 | 每塊板子的頻道照晶片編號錯開成 1、6、11，但還是可能擠 | 換位置、稍等再連；還不行就兩組輪流。⚠️ 全班同時開還沒驗過 |

## 九、學生不要做的

- **不要對 ESP32 上傳程式、刪檔、燒韌體**（`mpremote cp`、`mpremote rm`、`esptool` 這些都不要）。板子上的 `main.py` 是老師刷好的 W12 選單，弄壞了這堂課就不能用。
- **不要改 ESP32 的腳位**，也不要對 `ezkit.py` 已經用到的腳位再建一次 `Pin(...)` 或 `PWM(...)`（會搶腳，燈不聽話）。這條是給以後真的要改 ESP32 程式的時候（例如期末專題）：那時候去 maker-esp32 repo 改，照它的 `AGENTS.md`。
- 繼電器只接低電壓，不接家用電。

## 十、老師：還原與重刷

在 maker-esp32 資料夾：

```
./tools/upload.sh                                   # 全部檔案傳上去（main.py 會變回創客課選單）
uv run mpremote connect auto sleep 2 cp <w12 起始檔>/esp32/main_w12.py :main.py
uv run mpremote connect auto reset                  # 變回 W12 選單
./tools/upload.sh d10_wifi_web                      # 或 d11_ble_remote：開機直接跑那一課（main_w12 怪怪的時候的退路）
```

板子的韌體不是 v1.29.0、或跑著不理 Ctrl+C 的舊程式：照 maker-esp32 README 的「助教：重燒韌體」。
